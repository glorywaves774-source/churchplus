# Deploying ChurchPlus (GitHub + Render)

## 1. Put the code on GitHub

```bash
git init && git add . && git commit -m "ChurchPlus 1.0.0"
git branch -M main
git remote add origin git@github.com:<you>/churchplus.git
git push -u origin main
```

`.gitignore` already keeps out `.env`, databases, uploads and caches. Never commit secrets.

## 2. Create everything on Render (Blueprint)

1. Render dashboard → **New → Blueprint** → choose the repository. `render.yaml` creates:
   * **churchplus** – the web app (Gunicorn), health check `/healthz`;
   * **churchplus-send-messages** – every 5 minutes, sends scheduled SMS/WhatsApp/email;
   * **churchplus-daily-reminders** – 07:00 daily, birthday greetings and tomorrow's reminders;
   * **churchplus-billing** – nightly, ChurchPlus invoices, past-due notices and pauses;
   * **churchplus-db** – PostgreSQL 16; **churchplus-limits** – Key Value store for rate limits.
2. Open the environment group **churchplus-shared** and fill in every value marked *sync: false*
   (storage, email, SMS, WhatsApp, Paystack, Hubtel, `PUBLIC_BASE_URL`, `FIELD_ENCRYPTION_KEY`).
3. Deploy. Before each release Render runs: `flask db upgrade`, `sync-permissions`,
   `seed-plans` and `encrypt-secrets` (all safe to repeat).

### Create the first super administrator

Render → churchplus → **Shell**:

```bash
flask churchplus create-superadmin --email you@yourdomain.com
```

Sign in with it: platform staff land on **/platform** (churches, invoices, plans).

### Custom domain

Render → churchplus → Settings → Custom Domains → add `app.yourdomain.com`, create the CNAME
it shows, then set `PUBLIC_BASE_URL=https://app.yourdomain.com`. Church websites are at
`https://app.yourdomain.com/c/<workspace-id>`.

## 3. Environment variables

| Variable | Purpose |
|---|---|
| `SECRET_KEY` | Signs sessions and links. Generated by Render. Changing it signs everyone out. |
| `FIELD_ENCRYPTION_KEY` | Encrypts two-step sign-in keys. Generate with `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`. Keep a copy in your password manager: without it, two-step keys cannot be read. |
| `DATABASE_URL` | From the Render database. |
| `RATELIMIT_STORAGE_URI` | From the Key Value store (so limits hold across workers). |
| `PUBLIC_BASE_URL` | Used in emails and payment return links. |
| `STORAGE_BACKEND=s3`, `S3_*` | Private file storage (AWS S3, Cloudflare R2, Backblaze B2). |
| `MAIL_*` | SMTP for invitations, password resets and church emails. |
| `SMS_BACKEND`, `HUBTEL_SMS_*` or `ARKESEL_API_KEY` | Church SMS. Register each church's sender ID with the provider. |
| `WHATSAPP_BACKEND=meta`, `WHATSAPP_TOKEN`, `WHATSAPP_PHONE_NUMBER_ID` | WhatsApp Business Cloud API. |
| `PAYSTACK_SECRET_KEY` | Paystack payments for ChurchPlus subscriptions. Webhook URL: `https://<domain>/webhooks/paystack`. |
| `HUBTEL_PAY_CLIENT_ID`, `HUBTEL_PAY_CLIENT_SECRET`, `HUBTEL_MERCHANT_ACCOUNT` | Hubtel online checkout. Callback: `https://<domain>/webhooks/hubtel` (set automatically per payment). |
| `BILLING_GRACE_DAYS` | Days after an unpaid invoice before a church is paused (default 7). |
| `REGISTRATION_REQUIRES_APPROVAL` | `true` to approve each new church in the platform console. |

Production refuses to start without `SECRET_KEY` and a PostgreSQL `DATABASE_URL`.

## 4. Database migrations

Schema changes are Alembic migrations in `migrations/versions/` (0001 → 0008). They run
automatically before each deploy. Never drop or recreate the production database. To check by
hand: `flask db current`, `flask db upgrade`.

## 5. Backups and recovery

* Render PostgreSQL (paid plans) keeps **daily backups** with point-in-time recovery – enable it
  on the database's *Recovery* tab and test a restore into a new database once a quarter.
* Extra off-site copy (recommended weekly), from any machine with `pg_dump`:
  `scripts/backup.sh "$DATABASE_URL" backups/` – keeps 8 encrypted-at-rest dumps if you store them in an encrypted bucket.
* Restore: `pg_restore --clean --no-owner -d "$NEW_DATABASE_URL" backups/churchplus-YYYYMMDD.dump`,
  point `DATABASE_URL` at it, redeploy.
* Uploaded files live in your S3 bucket: turn on **versioning** and a lifecycle rule there.
* A single church can be exported any time: `flask churchplus export-church --slug <id> --out file.zip`
  (owners can also download it under Church settings).

## 6. Logging and monitoring

* Every response carries an `X-Request-ID`; every log line shows `[req …]`. When a user sees
  "Something went wrong", the page shows the reference to search for in Render → Logs.
* Requests slower than 2 seconds are logged as warnings.
* Point an uptime monitor (UptimeRobot, Better Stack…) at `https://<domain>/healthz`
  (checks the database too) and alert on failures of the three cron jobs in Render.
* Watch: failed SMS counts on the Communication page, overdue invoices in /platform.

## 7. Installable app

ChurchPlus is a Progressive Web App: on Android/Chrome, people tap **Install app**; on iPhone,
Share → **Add to Home Screen**. It needs HTTPS (Render provides it). Pages are never stored on
the device; only styles, scripts and icons are cached, with an offline notice when there is no
connection. Each release changes the cache version automatically.
